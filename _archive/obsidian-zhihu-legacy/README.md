# 知乎内容管道（第二代，2025-09 ~ 2025-10）—— 已废弃

这里保存的是接手前的**内容侧**管道：把知乎导出的文章整理成可入库的 Markdown。
它与第一代**渲染侧**管道（见 [../legacy-pipeline/](../legacy-pipeline/)）是同一件事的两半，
现由 `R Language/pipeline/` 统一取代。

> 脚本里的绝对路径原样保留，作为"当时就是这样写的"的证据。

---

## 一、它当时怎么工作

```
知乎「导出文章」
      │  文件名带后缀：<标题>-落日阳红的文章.md
      │  frontmatter 只有 tags 与 zhihu-link
      ▼
┌─────────────────────────────────────────┐
│ 阶段一：原始导出件                        │   ← 本次归档
│   【R 语言】broom 包进行整洁建模-落日阳红的文章.md
└─────────────────────────────────────────┘
      │  process_files.py
      │    1. 去掉文件名里的 -落日阳红的文章 后缀
      │    2. 用正则剥掉整个 YAML 头
      │    3. 把代码块语言统一改成 R
      ▼
┌─────────────────────────────────────────┐
│ 阶段二：processed_files/                 │
│   【R 语言】broom 包进行整洁建模.md        │
└─────────────────────────────────────────┘
      │  人工/AI 翻译
      ▼
┌─────────────────────────────────────────┐
│ 阶段三：translated_files/                │
│   【R Language】broom Package for Tidy Modeling.md
└─────────────────────────────────────────┘
      │  人工复制到仓库 R Language/ 下
      ▼
   仓库（平铺的英文 md，无 frontmatter）
```

## 二、为什么整条链路要废弃

| # | 问题 | 具体表现 |
| --- | --- | --- |
| 1 | **把最有用的字段丢了** | `process_files.py` 第 33 行用 `re.sub(r'^---\s*[\s\S]*?\s*---\s*', '', content, count=1)` 剥掉整个 YAML 头。原始导出件里的 `zhihu-link` 正是 `index.html` 卡片「中文-知乎」按钮需要的值，剥掉后只能靠人工在渲染侧再抄一遍 36 条字面量。 |
| 2 | **代码块语言一刀切** | `re.sub(r'(```)\s*[a-zA-Z0-9]+\s*$', '```R', ...)` 把所有围栏语言无条件改成 `R`。实测知乎导出件里 Rust 代码被标成 `text`、R 代码被标成 `ada`，一刀切成 `R` 后 Rust 代码块会被按 R 高亮，配色全乱。 |
| 3 | **正则剥 YAML 会误伤** | 该正则不锚定文件开头，正文里若出现 `---` 分隔线会被当作 YAML 边界。 |
| 4 | **三个阶段互不校验** | 阶段二丢了字段、阶段三换了语种，没有任何一步会比对"两侧是否配对成功"，全靠人工。 |
| 5 | **靠目录约定而非标识** | 三个阶段都用文件名传递身份，改名、加空格、改标点都会断链。 |
| 6 | **绝对路径** | `dir_path = r"d:\ObsidianDirectory\zhihu"` 写死。 |

## 三、本目录收录范围

**收录**

| 内容 | 理由 |
| --- | --- |
| `source/*-落日阳红的文章.md`（10 篇） | 唯一不可再生的一环：知乎导出的原始件，含 `zhihu-link` |
| `source/process_files.py` | 承载"当时怎么转换的"这一信息 |

**主动排除**

| 排除项 | 理由 |
| --- | --- |
| `processed_files/`（9 篇） | 由 `process_files.py` 从原件确定性产出，可复现；且其内容已以更好形态进入 `R Language/zh/` |
| `translated_files/`（9 篇） | 译文已进入 `R Language/en/` 并补上了 frontmatter |

两者都未丢失：它们的内容已随本次重构进入仓库正文，
只是不再以"中间产物"的身份单独存在。

## 四、被什么取代

见 [R Language/pipeline/](../../R%20Language/pipeline/)：

| 旧做法 | 新做法 |
| --- | --- |
| 剥掉 YAML 头，字段靠人工抄 | frontmatter 是唯一数据源，`zhihu-link` 直接来自它 |
| 代码块语言一刀切成 `R` | 按内容嗅探（`normalize.detect_language`），识别 r / rust / toml / bash / 目录树 |
| 文件名传递身份 | `slug` 是显式配对键（`en/<slug>/` 与 `zh/<slug>/`） |
| 三阶段无校验 | `check` 子命令校验字段、图片、配对、前缀、产物隔离 |
| 绝对路径 | 路径从文件位置反推；库根按 命令行 → 环境变量 → 配置 → 自动探测 |

一次性迁移由 `rlang_pipeline.migrate` 完成，映射数据在
[`vault-map.toml`](../../R%20Language/pipeline/vault-map.toml)。
