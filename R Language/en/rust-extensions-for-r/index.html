<h3>I. The Core Mental Model</h3> <p>R does not know Rust. What R knows is a C dynamic library (<code>.dll</code> / <code>.so</code> / <code>.dylib</code>).</p> <p>Loading an extension package in R is, at bottom, <code>dyn.load()</code> on a dynamic library, followed by <code>.Call()</code> to invoke functions in it that follow the C ABI. Rcpp works because C++ can compile a dynamic library that exposes the C ABI. extendr works because <strong>Rust can compile a C-ABI dynamic library too</strong>.</p> <p>What <code>{extendr}</code> does is generate two layers of glue automatically:</p> <table> <thead> <tr> <th>Layer</th> <th>Job</th> </tr> </thead> <tbody> <tr> <td>Rust side</td> <td>Uses the #[extendr] macro to wrap functions as extern "C", and handles conversion between R objects and Rust types</td> </tr> <tr> <td>R side</td> <td>Generates .Call() wrapper functions and NAMESPACE exports</td> </tr> </tbody> </table> <p>You write Rust functions and call them from R like ordinary functions. What R sees is still a C dynamic library.</p> <p><code>{extendr}</code> is the collective name for a group of crates (<code>extendr-api</code>, <code>extendr-engine</code>, <code>extendr-macros</code>). It occupies the same niche as Rcpp/cpp11, but underneath it is Rust. <code>{rextendr}</code> is the companion package on the R side, handling scaffold generation and toolchain management. extendr's design goal is to offer an opinionated API, drawing heavily on the ergonomics of Rcpp and cpp11.</p> <h3>II. Environment Setup and Health Check</h3> <p><img alt="" src="https://pic3.zhimg.com/v2-6f28b147f6d999a41bfedbc428ce19ec_1440w.jpg"></p> <p>rextendr</p> <p>Before you start, make sure three things are in place:</p> <ol> <li><strong>Rust toolchain</strong>: install <code>rustup</code> from <a href="http://rust-lang.org">Rust Programming Language</a>. extendr's current minimum supported Rust version (MSRV) is 1.65.0, which keeps it CRAN-compliant. Windows users need to add the GNU toolchain as well: <code>rustup target add x86_64-pc-windows-gnu</code></li> <li><strong>R version</strong>: R &gt;= 4.2.0 is recommended</li> <li><strong>R packages</strong>: install <code>install.packages(c("rextendr", "usethis", "devtools"))</code> in R</li> <li><strong>One-shot health check</strong>: run the command below — all green checkmarks and you can begin:</li> </ol> <div class="highlight"><pre><span></span><code><span class="n">rextendr</span><span class="o">::</span><span class="nf">rust_sitrep</span><span class="p">()</span> </code></pre></div> <p><code>rust_sitrep()</code> produces a detailed report on your current Rust infrastructure, along with suggestions for fixing whatever is not in order.</p> <h3>III. Experiment First, Build the Package Later</h3> <p>Do not start by creating a package. First verify your core logic in the R console with <code>rust_function()</code>:</p> <div class="highlight"><pre><span></span><code><span class="n">rextendr</span><span class="o">::</span><span class="nf">rust_function</span><span class="p">(</span><span class="s">"</span> <span class="s">fn add_one(x: f64) -&gt; f64 {</span> <span class="s"> x + 1.0</span> <span class="s">}</span> <span class="s">"</span><span class="p">)</span> </code></pre></div> <p>Then call it directly:</p> <div class="highlight"><pre><span></span><code><span class="nf">add_one</span><span class="p">(</span><span class="m">5</span><span class="p">)</span> <span class="c1"># [1] 6</span> </code></pre></div> <p>The purpose of this step is to turn "Rust code running inside R" from an abstraction into something concrete. Once you have confirmed that the function logic is correct and the performance gain meets expectations, build the package for real.</p> <p>As a compiled language, Rust converts code to machine language before running it, so it executes far faster than an interpreted language like R. The standard way to pair a compiled language with R is: use <code>Rprof()</code> to find the bottlenecks, rewrite the very slow parts in a compiled language, then write an R function to call it. Compared with C++, Rust has stricter code validation and memory-safety mechanisms, and its error messages are friendlier to beginners.</p> <h3>IV. The Complete Package Structure: What Each File Is and Which Ones You Should Touch</h3> <p>Run the following commands to create the package and inject the scaffold:</p> <div class="highlight"><pre><span></span><code><span class="n">usethis</span><span class="o">::</span><span class="nf">create_package</span><span class="p">(</span><span class="s">"mypkg"</span><span class="p">)</span> <span class="n">rextendr</span><span class="o">::</span><span class="nf">use_extendr</span><span class="p">()</span> </code></pre></div> <p><code>use_extendr()</code> generates the following files in your package directory:</p> <div class="highlight"><pre><span></span><code>mypkg/ ├── R/ │ └── extendr-wrappers.R ← auto-generated, do not touch ├── src/ │ ├── .gitignore ← usually no need to touch │ ├── Makevars.in ← do not touch │ ├── Makevars.win.in ← do not touch │ ├── entrypoint.c ← do not touch │ ├── mypkg-win.def ← do not touch │ └── rust/ │ ├── Cargo.toml ← editable (add dependencies here) │ ├── document.rs ← do not touch │ └── src/ │ └── lib.rs ← this is where you write Rust ├── tools/ │ ├── config.R ← do not touch │ └── msrv.R ← do not touch ├── cleanup / cleanup.win ← do not touch └── configure / configure.win ← do not touch </code></pre></div> <p><strong>You only need to edit three files</strong>:</p> <table> <thead> <tr> <th>File</th> <th>What you do</th> </tr> </thead> <tbody> <tr> <td>src/rust/src/lib.rs</td> <td>Write Rust functions — this is the core</td> </tr> <tr> <td>src/rust/Cargo.toml</td> <td>Add Rust dependencies</td> </tr> <tr> <td>src/.gitignore</td> <td>Occasionally needed, usually you can ignore it</td> </tr> </tbody> </table> <p><strong>Every other file is build-system plumbing.</strong> Do not edit them by hand. If <code>use_extendr()</code> is run again, it will overwrite these files.</p> <p><strong>What the key files do</strong>:</p> <ul> <li><strong><code>R/extendr-wrappers.R</code></strong> —— the interface layer on the R side. It is regenerated automatically every time you run <code>devtools::document()</code>, and it holds the R wrappers for your Rust functions. <strong>Never edit it by hand</strong>.</li> <li><strong><code>src/entrypoint.c</code></strong> —— the C entry point R uses when it loads the dynamic library. R does not know Rust, but it knows C.</li> <li><strong><code>src/Makevars.in</code></strong> —— tells R's build system: when compiling this package, first invoke cargo to compile the Rust, then link the result in.</li> <li><strong><code>src/rust/Cargo.toml</code></strong> —— the Rust-side "DESCRIPTION". The crate is built in two forms at once: <code>rlib</code> (so the document binary can introspect the exports) and <code>staticlib</code> (linked into the R package). The <code>[[bin]]</code> entry registers <code>document.rs</code>, which generates the R wrapper functions at build time.</li> <li><strong><code>src/rust/document.rs</code></strong> —— a build-time tool that scans functions marked with <code>#[extendr]</code> and generates <code>R/extendr-wrappers.R</code>.</li> <li><strong><code>src/rust/src/lib.rs</code></strong> —— your main Rust source file. The <code>extendr_module!</code> macro controls which functions, impl blocks, and submodules are exposed to R. <strong>Every function you want available from R must be listed in <code>extendr_module!</code></strong>.</li> </ul> <h3>V. Type Mapping Between R and Rust</h3> <p>This is the key to understanding how extendr works. extendr builds a type bridge on top of R's C API (which is based on <code>SEXP</code> pointers), and every R object type has a corresponding wrapper struct in extendr.</p> <p>Scalar types</p> <p>R has no notion of scalars (everything is a vector), and Rust has no notion of NA. extendr provides dedicated scalar types for exactly this reason:</p> <table> <thead> <tr> <th>R type</th> <th>Rust native type</th> <th>extendr wrapper type</th> </tr> </thead> <tbody> <tr> <td>integer(1)</td> <td>i32</td> <td>Rint</td> </tr> <tr> <td>logical(1)</td> <td>bool</td> <td>Rbool</td> </tr> <tr> <td>double(1)</td> <td>f64</td> <td>Rfloat</td> </tr> <tr> <td>character(1)</td> <td>String</td> <td>Rstr</td> </tr> <tr> <td>complex(1)</td> <td>Complex<f64></td> <td>Rcplx</td> </tr> </tbody> </table> <p>Vector types</p> <p>In R everything is a vector. extendr provides matching vector wrapper types:</p> <table> <thead> <tr> <th>R type</th> <th>extendr type</th> <th>C API type</th> </tr> </thead> <tbody> <tr> <td>integer()</td> <td>Integers</td> <td>INTSXP</td> </tr> <tr> <td>double()</td> <td>Doubles</td> <td>REALSXP</td> </tr> <tr> <td>logical()</td> <td>Logicals</td> <td>LGLSXP</td> </tr> <tr> <td>character()</td> <td>Strings</td> <td>STRSXP</td> </tr> <tr> <td>raw()</td> <td>Raw / &amp;[u8]</td> <td>RAWSXP</td> </tr> <tr> <td>list()</td> <td>List</td> <td>VECSXP</td> </tr> </tbody> </table> <p><strong>Performance tip</strong>: use extendr wrapper types rather than Rust's native <code>Vec&lt;T&gt;</code> wherever you can. Accepting or returning a <code>Vec&lt;T&gt;</code> requires an extra memory allocation, which adds overhead. That is fine when you can tolerate the cost, but if an extendr type will do the job, prefer it.</p> <p>Type conversion</p> <p>extendr converts between R and Rust values through the <code>From</code>, <code>Into</code>, and <code>TryFrom</code> traits. <code>Robj</code> is the wrapper around all R SEXP pointers: it can create R objects from Rust types and iterators, and it can convert in both directions to and from Rust vectors.</p> <h3>VII. configuration</p> <p><strong>Installing rust-analyzer is strongly recommended</strong>. If you use VS Code or Positron, it provides type hints and autocompletion suggestions.</p> <p>Run the following command to configure it automatically:</p> <div class="highlight"><pre><span></span><code><span class="n">rextendr</span><span class="o">::</span><span class="nf">use_vscode</span><span class="p">()</span> </code></pre></div> <p>By default rust-analyzer looks for <code>Cargo.toml</code> in the workspace root. This function creates <code>.vscode/settings.json</code> and points the workspace root at <code>src/rust/</code>, so the extension works properly. As of rextendr 0.4, if you use VS Code or Positron, running <code>use_extendr()</code> calls <code>use_vscode()</code> for you.</p> <h3>X. Publishing to CRAN</h3> <p>extendr packages are CRAN-compatible out of the box. There is just one extra step you need to take — <strong>vendor your Rust dependencies</strong>:</p> <div class="highlight"><pre><span></span><code><span class="n">rextendr</span><span class="o">::</span><span class="nf">vendor_crates</span><span class="p">()</span> </code></pre></div> <p>10.1 Why vendoring is necessary</p> <p>CRAN cares a great deal about portability. An R package must contain everything needed to build it, which means Rust dependencies cannot be downloaded from the internet at install time. Vendoring means embedding the source code of your dependencies into your R package. <code>vendor_crates()</code> creates a <code>vendor.tar.xz</code> file containing the compressed source of all dependencies.</p> <p>10.2 Things to watch out for</p> <ul> <li><code>vendor_pkgs()</code> is deprecated, use <code>vendor_crates()</code> instead</li> <li>Depending on the number of dependencies, <code>vendor.tar.xz</code> can reach several MB</li> <li>Note the package size in <code>cran-comments.md</code>, for example: "Tarball is 4.7mb due to vendored rust dependencies"</li> <li>The current CRAN MSRV is 1.81, and your package must satisfy it</li> <li>CRAN does not support nightly features</li> </ul> <h3>XI. Advanced Features</h3> <p>11.1 Async Rust (Tokio)</p> <p>extendr does not offer an async function interface, because R has no real async runtime. But that does not mean you cannot take advantage of Rust's vast async ecosystem. Many crates (such as <code>reqwest</code>, <code>axum</code>, <code>DataFusion</code>, <code>sqlx</code>) are built on the Tokio runtime.</p> <p>How to enable it:</p> <div class="highlight"><pre><span></span><code><span class="n">rextendr</span><span class="o">::</span><span class="nf">use_msrv</span><span class="p">(</span><span class="s">"1.70"</span><span class="p">)</span> <span class="n">rextendr</span><span class="o">::</span><span class="nf">use_crate</span><span class="p">(</span><span class="s">"tokio"</span><span class="p">,</span><span class="w"> </span><span class="n">features</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"rt-multi-thread"</span><span class="p">)</span> </code></pre></div> <p>Define a shared Tokio runtime in <code>lib.rs</code>, using <code>OnceLock</code> for thread-safe lazy initialization. Then, whenever you need to call an async function, execute the future with <code>.block_on()</code>.</p> <p>11.2 WebR support</p> <p>As of rextendr 0.4, every extendr-powered R package is WebR-compatible out of the box, which means your package can run in the browser with no R installation. WebR support requires no extra work from you.</p> <p><strong>Note</strong>: WebR support requires <code>lto = true</code> in the release profile of <code>Cargo.toml</code>. New packages handle this automatically, but existing packages need to add it manually. Not every Rust crate is wasm-compatible.</p> <h3>XII. Who Is Already Using It</h3> <p>extendr already has a set of production R packages spanning several domains:</p> <ul> <li><strong>dialrs</strong>: an R package for parsing phone numbers</li> <li><strong>arcgisgeocode</strong>: geocoding tools</li> <li><strong>rsgeo</strong>: geospatial geometry operations</li> <li><strong>arcgisplaces</strong>: place search</li> <li><strong>salso</strong>, <strong>caviarpd</strong>, <strong>fangs</strong>: Rust-powered R packages already published on CRAN</li> </ul> <p>A study modeling African swine fever (ASF) in wild boar demonstrates extendr's practical value: the researchers used Rust to build a custom sparse, cache-friendly data structure for tracking infection pressure — a data structure that is not achievable in R. extendr let this complex data structure coexist seamlessly with native R code and data structures, delivering a significant boost in computational performance.</p> <h3>XIII. What You Don't Need to Worry About Right Now</h3> <p><code>configure</code>, <code>cleanup</code>, <code>Makevars.in</code>, <code>entrypoint.c</code>, <code>document.rs</code> — these are build-system plumbing. They exist so that <code>devtools::document()</code> can handle compilation and linking automatically. You do not need to change them, and you do not need to understand their internals.</p> <h3>One-Sentence Summary</h3> <p><strong><code>lib.rs</code> is where you write your code, <code>Cargo.toml</code> is where you add dependencies, and every other file is generated plumbing.</strong> Validate in the console with <code>rust_function()</code> first, then build the package; write Rust functions, compile with <code>devtools::document()</code>, load with <code>devtools::load_all()</code>, and call them from R like ordinary functions.</p> <p><a href="http://rust-lang.org">Rust Programming Language</a><a href="https://extendr.rs/rextendr/">https://extendr.rs/rextendr/</a></p>
